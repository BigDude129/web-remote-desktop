# 결정 기록

## 입력 거부와 화면 연결 분리 / 2026-10-15 / 수정

사용자의 iPad 접속이 약 7초·1초 뒤 종료된 기록 두 건에서 원인은 input_failed였다. 게임 캡처 실패로 단정하지 않는다. 기존 버전은 입력 거부 하나로 캡처를 중단해 원격 세션을 종료했다. 0.1.1에서는 Windows API 입력 거부를 별도 경고로 처리하고 화면을 유지한다. 입력은 일시 정지 후 사용자 재시도로만 재개하며 실패 종류·Windows 오류 번호를 기록한다. 실제 입력 내용은 기록하지 않는다. 게임/권한 원인 판별과 실제 제어 호환성은 후속 재시험 사항이다.

## Oracle 임시 HTTPS 배포 / 2026-10-15 / 테스트 적용

사용자의 바로 접속 가능한 테스트 링크 요청에 따라 기존 Oracle의 별도 프로세스와 임시 Cloudflare 터널로 배포했다. 기존 서비스의 런타임·터널을 교체하지 않고 별도 사본을 사용한다. 고정 도메인/인증서 준비 전 외부 로그인/WSS를 확인하기 위한 선택이며 상시 운영·무인 접속 완료를 의미하지 않는다. 경로에 Cloudflare가 추가되므로 Oracle 단독 중계의 트래픽·지연 결과로 해석하지 않는다. 실제 계정·주소는 공개 Git에 기록하지 않는다.

## Oracle 외부 접속 파일럿 / 2026-10-15 / 확정 방향·환경 미정

사용자는 기존 Oracle를 연결해 구현 가능성을 확인하도록 요청했다. 현재 서버 중계 MVP를 Oracle VM에 배치하여 외부 LTE/5G 접속을 우선 검증한다. 직결 우선 제안은 이 파일럿에서는 보류하며 실제 중계 전송량과 계정 무료 한도를 확인한다. 기존 SSH 설정으로 VM과 운영 서비스 점검을 완료했다. 기존 Node를 교체하지 않고 전용 런타임/포트/데이터 경로를 사용하는 방향이며 도메인과 외부 공개 경로는 미정이다. [준비 및 판정 기준](oracle-pilot.md)을 따른다.

## D-006 / 2026-10-15 / 확정: Windows 우선 실제 화면 MVP

사용자가 웹 로그인, 서버의 기기 목록, 로그인한 agent의 원격 수행을 요청하고 'Windows 우선, 실제 화면 제어 MVP'를 선택했다. D-001의 문서 전용 단계에서 실행 코드로 확장한다. main 커밋·푸시, rules/rules.md 신규 규칙 기록을 명시적으로 요청했다. 인터넷 공개/공유기 변경은 수행하지 않는다.

## D-007 / 2026-10-15 / 구현 선택: 관리/전송 계층 분리

Node 24/TypeScript/Express/SQLite 서버, React 웹, .NET 10 Windows Forms 에이전트로 구성한다. 외부 DB 설치 없이 인증/기기를 영속화하고 Windows 캡처·입력을 네이티브로 구현하기 위한 선택이다. Rust/Electron/PostgreSQL도 대안이나 초기 실행 복잡도를 줄인다. 다중 서버/조직 도입 시 SQLite와 메모리 presence를 재검토한다.

## D-008 / 2026-10-15 / 구현 선택: 초기 전송은 콘솔 JPEG/WebSocket

기본 화면 최대 1600×900/목표 5 FPS와 입력 중계를 독립 구현한다. MeshCentral의 server/agent 구조와 Guacamole의 인증/원격 엔진 분리를 참고했으며 소스는 복사하지 않았다. Microsoft RDP라고 표시하지 않는다. D-002/003의 고성능 엔진/직결 제안은 후속 후보다. 현재 영상은 서버를 경유하므로 클라우드 중계 비용이 있을 수 있다. GPU/오디오/대역폭 요구가 커지면 WebRTC/Sunshine/Guacamole 어댑터로 교체한다.

## D-009 / 2026-10-15 / 구현 선택: 명시적 허용과 계정 격리

공개 회원가입/기본 비밀번호 없이 로컬 CLI로 계정을 생성한다. 웹/agent 로그인 분리, 자기 소유 기기만 제어, 1기기 1제어자, 만료/철회, agent 토큰 메모리 보관을 적용한다. GUI 로그인/원격 허용 뒤 활성화하며 Windows 서비스/자동 로그인은 하지 않는다. 잠금/UAC/로그온 전은 별도 설계가 필요하다. MFA·조직 권한·계정 수명주기는 외부 공개 전 후속 작업이다.

## D-011 / 2026-10-15 / 확정: MIT와 의존성 고지

사용자가 라이선스 고지를 요청하고 선택 질문에 MIT로 답했다. 저장소 자체 LICENSE와 package.json을 MIT로 설정한다. 직접·전이 npm 의존성의 설치된 원문 LICENSE/NOTICE를 빌드 때 수집해 웹에서 제공하고, 에이전트 ZIP에는 사용한 .NET runtime pack의 원문 고지를 포함한다. 각 의존성의 라이선스는 유지하며 프로젝트 MIT로 덮지 않는다.

## D-012 / 2026-10-15 / 확정 및 구현 선택: 최신 릴리즈 agent 제공

사용자가 버전업 시 최신 릴리즈 에이전트를 제공하도록 요청했다. package.json을 버전 기준으로 하고 CLI로 .NET/lock 버전을 함께 변경한다. vX.Y.Z 태그의 서버/웹/Windows 검증 성공 후 draft Release에 versioned ZIP, SHA256SUMS, manifest를 올리고 마지막에 공개한다. 웹은 GitHub latest 안정 릴리즈를 우선 제공하고 로컬 개발 패키지는 구분해서 제공한다. agent는 로그인 후/수동으로 새 버전을 확인하고 릴리즈 페이지를 연다. 사용자의 원격 작업을 끊는 자동 교체/실행은 하지 않는다. hash는 다운로드 무결성 값이며 게시자 서명을 대체하지 않는다. 코드 서명/자동 업데이트 설치기는 후속 범위다.

## D-013 / 2026-10-15 / 확정 및 구현 선택: VM 설치·웹 제어 검증

사용자는 1차 main 푸시 이후 가상 PC에 agent를 설치해 실제 웹 동작을 검사하고 문제 수정/커밋/푸시를 이어가도록 요청했다. 후속 변경도 이 명시적 main 반영 요청에 포함한다. GitHub Windows VM에서 배포 ZIP을 웹으로 다운로드·검증·압축 해제하고 실제 GUI 로그인, 캡처, 클릭, 키보드, 한글, 휠, 드래그, modifier 해제, 재연결, agent 로그아웃을 검사한다. 별도 테스트 창은 Windows 이벤트를 관측하며 프로덕션 입력 경로를 대체하지 않는다. 실제 VM 실행/통과 여부는 Actions 결과로만 확정한다.

## D-014 / 2026-10-15 / 확정 및 구현 선택: Actions 저장 의존성 제거

사용자가 Actions 한도 소진 가능성을 알려왔으며 공개 저장소/표준 러너의 실행 시간 무료 정책을 확인한 뒤 계속 진행하도록 요청했다. 계정 전체의 저장공간/결제 상태를 확인했다는 뜻은 아니다. 기존 D-012의 job 간 artifact 전달을 없애고 Windows VM 한 곳에서 패키징→웹 다운로드/설치→실제 제어 검증→동일 ZIP 게시를 수행한다. Actions 캐시/아티팩트 업로드 없이 job summary/로그에 결과를 남긴다. 비공개 저장소에서는 자동 검사 실행을 건너뛰고 비용 정책을 재검토한다. [GitHub 과금 기준](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

## D-015 / 2026-10-15 / 구현 선택: CI 실행 엔진 지원 갱신

첫 main/태그 CI는 모두 검증을 통과했으나 기존 v4 action의 Node 20 실행 엔진이 Node 24로 강제 전환된다는 경고가 발생했다. 공식 릴리즈와 `action.yml`을 확인하여 checkout 7.0.1, setup-node 7.1.0, setup-dotnet 6.0.0의 Node 24 지원 버전을 정확한 SHA로 고정한다. setup-node의 자동 패키지 캐시 기본값을 검토하고 `package-manager-cache: false`, .NET `cache: false`를 명시한다. checkout의 자격증명 보관도 두 job 모두 끈다. 이미 게시한 v0.1.0은 검증된 기존 태그/ZIP을 유지하며 이 CI 개선을 소급하여 바이너리를 교체하지 않는다. 출처/라이선스는 benchmarks에 기록한다.

## D-016 / 2026-10-15 / 확정 및 구현 선택: 웹 전체 글자 확대

사용자가 웹 전반의 글자가 작다고 지적하고 수정 후 main 커밋·푸시, 수정 전 pull을 요청했다. 로컬 작업 트리가 깨끗한 상태에서 `git pull --ff-only origin main`을 실행했고 기준 커밋 `60b066a`가 최신임을 확인했다. 로그인, 탐색, 기기 카드/검색/필터, 연결 기록, 설치/릴리즈 안내, 원격 뷰어의 6~15px 고정 글자를 공통 rem 크기로 전환한다. 기본 16px 브라우저 설정에서 본문·입력·주요 버튼 16px, 보조 글자 14px, 카드 제목 18px, 주요 제목 24~32px로 계층을 맞춘다. 기존 로그인 소개의 큰 제목은 상대 단위로 유지한다.

글자가 커진 만큼 로그인 폼/사이드바/설치 창 폭과 입력/버튼 높이를 늘리고, 기기 카드 자동 열 배치, 제목 단어 단위 줄바꿈, 긴 기기명/서버 주소/해시 줄바꿈, 탐색/뷰어 도구 모음의 줄바꿈을 적용한다. 모바일에 별도의 작은 글자를 다시 적용하지 않는다. 루트 글자 확대에서도 통계 설명이 카드 밖으로 나오지 않도록 고정 한 줄 제약을 제거했다. 원격 canvas의 화면 내용과 좌표 계산, 인증/API, Windows agent는 변경하지 않는다. 앱 버전과 게시한 v0.1.0 에이전트는 유지하며 웹 변경은 Unreleased로 기록한다. 검증 범위와 결과는 validation의 웹 글자 확대 항목에 기록한다.

## 후속 결정 양식

### 2026-10-15 / Windows 대문자 잠금 복구

사용자는 iPad 한영 전환 성공 후 영문이 계속 대문자가 된다고 보고했다. 읽기 전용 호스트 진단에서 Caps Lock 켜짐, 양쪽 Shift 해제를 확인했다. 이전 매핑에서 남은 상태일 가능성이 있으나 켜진 시점은 확정하지 않는다. Lang1 매핑은 Windows Caps Lock을 해제하지 않는다. 현재 프로토콜에는 호스트 잠금 상태가 없으므로 연결 시 무조건 CapsLock을 보내면 오히려 잠금을 켤 수 있다. 키보드 설정에 명시적 `PC Caps Lock 전환` 버튼을 추가하고, release 뒤 기존 CapsLock down/up을 전송하고 canvas로 초점을 돌린다. 실제 잠금 상태나 자동 해제를 보장하는 표시를 하지 않는다.

### 2026-10-15 / iPad 키보드 및 게임 후속 진단

사용자는 iPad 연결 끊김이 크게 줄었지만 게임 실행 중 문제와 Caps Lock 한영 전환 실패가 남았다고 보고했다. 게임 테스트 감사 기록은 `input.blocked.move.0`으로, SetCursorPos 실패를 확인했으나 원인이나 캡처 정상 여부를 확정하지 않는다. 게임과 agent의 권한 차이는 조사 대상이며 관리자 실행이나 게임 보안 우회는 자동 적용하지 않는다.

웹은 iPad 감지 시 Caps Lock을 기존 Lang1 한 번 누름/해제로 변환한다. keyup 누락에 대비해 keydown에서 쌍을 보내고 repeat/keyup은 무시한다. 다른 기기는 기본 매핑을 유지하며 사용자가 옵션을 바꿀 수 있다. 설정은 브라우저 localStorage에만 저장하고 저장 불가 시 해당 세션에 적용한다. 원격 canvas에만 적용해 로컬 문자열 조합을 간섭하지 않는다. iPadOS가 선처리한 키는 복구할 수 없으므로 OS 설정과 화면 한/영 버튼을 안내한다. [Apple 설정 안내](https://support.apple.com/en-euro/guide/ipad/ipaddd28d7ed/ipados).
