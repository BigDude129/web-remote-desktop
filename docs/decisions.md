# 결정 기록

## D-001 / 2026-10-15 / 확정: 보완 수단과 문서 우선

사용자 요청에 따라 Jump Desktop을 보완하는 웹 원격 제어를 기획하고 rules/setting.txt와 Git 이력을 만든다. 이번 단계는 기획이며 서비스 설치·인터넷 공개·공유기 변경은 포함하지 않는다.

## D-002 / 2026-10-15 / 제안: 기존 엔진 우선 검증

Sunshine + MrCreativ3001/moonlight-web-stream을 첫 후보로 한다. 캡처·GPU 인코딩·프로토콜을 처음부터 개발하는 비용을 줄이고 한영·터치 개선에 집중한다. 실제 기기 검증 실패 시 MeshCentral 또는 네이티브 Moonlight와 비교한다. 아직 채택 확정이 아니다.

## D-003 / 2026-10-15 / 제안: PC 측 게이트웨이와 직접 영상 연결 우선

클라우드 영상 중계 비용을 줄이기 위해 게이트웨이를 PC/같은 LAN에 둔다. VPN 허용 여부와 외부 접속망 조사 후 공개 HTTPS 또는 VPN 방식을 결정한다. 직접 연결 실패 시 무료로 항상 복구된다는 보장은 하지 않는다.

## D-004 / 2026-10-15 / 일부 확정: 감독모드와 VPN

사용자는 감독모드에서 연속경기를 진행하기 위한 몇 차례의 수동 클릭이 목적이라고 확인했다. 실제 경기 플레이와 자동 클릭 매크로는 개발 범위에 포함하지 않는다. VPN 앱 최초 설치 허용 여부는 미정이다.

## D-005 / 2026-10-15 / 확정: 공개 GitHub 협업

사용자 요청으로 공개 저장소를 생성한다. 개인 환경 상세는 Git 제외 경로 local/에 보관하고, 요구사항 변경과 버그 제보를 이슈·Pull Request로 관리한다. 지인의 직접 쓰기 권한은 계정을 확인해 별도로 부여할 수 있으며 초기에는 Fork/PR로 참여 가능하다.

## D-006 / 2026-10-15 / 확정: Windows 우선 실제 화면 MVP

사용자가 웹 로그인, 서버의 기기 목록, 로그인한 agent의 원격 수행을 요청하고 'Windows 우선, 실제 화면 제어 MVP'를 선택했다. D-001의 문서 전용 단계에서 실행 코드로 확장한다. main 커밋·푸시, rules/rules.md 신규 규칙 기록을 명시적으로 요청했다. 인터넷 공개/공유기 변경은 수행하지 않는다.

## D-007 / 2026-10-15 / 구현 선택: 관리/전송 계층 분리

Node 24/TypeScript/Express/SQLite 서버, React 웹, .NET 10 Windows Forms 에이전트로 구성한다. 외부 DB 설치 없이 인증/기기를 영속화하고 Windows 캡처·입력을 네이티브로 구현하기 위한 선택이다. Rust/Electron/PostgreSQL도 대안이나 초기 실행 복잡도를 줄인다. 다중 서버/조직 도입 시 SQLite와 메모리 presence를 재검토한다.

## D-008 / 2026-10-15 / 구현 선택: 초기 전송은 콘솔 JPEG/WebSocket

기본 화면 최대 1600×900/목표 5 FPS와 입력 중계를 독립 구현한다. MeshCentral의 server/agent 구조와 Guacamole의 인증/원격 엔진 분리를 참고했으며 소스는 복사하지 않았다. Microsoft RDP라고 표시하지 않는다. D-002/003의 고성능 엔진/직결 제안은 후속 후보다. 현재 영상은 서버를 경유하므로 클라우드 중계 비용이 있을 수 있다. GPU/오디오/대역폭 요구가 커지면 WebRTC/Sunshine/Guacamole 어댑터로 교체한다.

## D-009 / 2026-10-15 / 구현 선택: 명시적 허용과 계정 격리

공개 회원가입/기본 비밀번호 없이 로컬 CLI로 계정을 생성한다. 웹/agent 로그인 분리, 자기 소유 기기만 제어, 1기기 1제어자, 만료/철회, agent 토큰 메모리 보관을 적용한다. GUI 로그인/원격 허용 뒤 활성화하며 Windows 서비스/자동 로그인은 하지 않는다. 잠금/UAC/로그온 전은 별도 설계가 필요하다. MFA·조직 권한·계정 수명주기는 외부 공개 전 후속 작업이다.

## D-010 / 2026-10-15 / 확정 및 구현 선택: 상세 협업 기록

rules/rules.md, AGENTS.md, 실행/아키텍처/프로토콜/벤치마킹/검증/인수인계 문서를 추가한다. 초기 main 직접 반영은 이번 요청에 따른다. 이후 기본은 PR. CI는 서버/웹과 Windows 빌드/패키지를 분리한다. ZIP/DB/원본 화면/비밀값은 소스에서 제외한다. 앱 버전 0.1.0과 기존 기획 v0.3.0을 구분한다.

## D-011 / 2026-10-15 / 확정: MIT와 의존성 고지

사용자가 라이선스 고지를 요청하고 선택 질문에 MIT로 답했다. 저장소 자체 LICENSE와 package.json을 MIT로 설정한다. 직접·전이 npm 의존성의 설치된 원문 LICENSE/NOTICE를 빌드 때 수집해 웹에서 제공하고, 에이전트 ZIP에는 사용한 .NET runtime pack의 원문 고지를 포함한다. 각 의존성의 라이선스는 유지하며 프로젝트 MIT로 덮지 않는다.

## D-012 / 2026-10-15 / 확정 및 구현 선택: 최신 릴리즈 agent 제공

사용자가 버전업 시 최신 릴리즈 에이전트를 제공하도록 요청했다. package.json을 버전 기준으로 하고 CLI로 .NET/lock 버전을 함께 변경한다. vX.Y.Z 태그의 서버/웹/Windows 검증 성공 후 draft Release에 versioned ZIP, SHA256SUMS, manifest를 올리고 마지막에 공개한다. 웹은 GitHub latest 안정 릴리즈를 우선 제공하고 로컬 개발 패키지는 구분해서 제공한다. agent는 로그인 후/수동으로 새 버전을 확인하고 릴리즈 페이지를 연다. 사용자의 원격 작업을 끊는 자동 교체/실행은 하지 않는다. hash는 다운로드 무결성 값이며 게시자 서명을 대체하지 않는다. 코드 서명/자동 업데이트 설치기는 후속 범위다.
