# 프로젝트 작업 규칙

갱신: 2026-10-15. 이 문서는 앞으로 추가되는 작업 규칙의 기준이다. 과거 기획의 사실과 검증 상태는 `docs/`에서 유지한다.

## 요구사항과 범위

- RULE-001: 웹 로그인, 서버에 영속 저장되는 사용자별 기기 목록, 로그인한 Windows 에이전트의 실제 화면 제어를 첫 MVP 범위로 한다. 사용자가 2026-10-15 Windows 우선 구현을 선택했다.
- RULE-002: 현재 Windows 콘솔을 공유한다. 자체 화면 전송을 Microsoft RDP 프로토콜 호환으로 표현하지 않는다. RDP/Guacamole 및 고성능 영상 엔진은 어댑터 확장 후보다.
- RULE-003: 구현 완료, 자동 검증 통과, 실기기 검증 완료를 구분한다. 모바일·게임·UAC·잠금 화면·고성능 스트리밍을 시험 없이 지원한다고 적지 않는다.

## 인증과 원격 제어

- RULE-004: 계정 생성은 서버 운영자의 로컬 CLI로 시작한다. 기본 비밀번호나 공개 회원가입을 제공하지 않는다. 비밀번호는 salt를 사용해 해시하고 인증 토큰은 서버에 해시로 저장한다.
- RULE-005: 기기 목록·세션·감사 이벤트는 사용자 소유권으로 격리한다. 웹 세션과 에이전트 세션을 분리하고 로그아웃·만료·연결 종료 시 관련 원격 제어를 해제한다.
- RULE-006: 에이전트는 로그인 및 사용자의 원격 허용 동작 이후에만 활성화한다. 화면 캡처는 원격 세션 동안만 수행한다. 에이전트에 연결 상태와 즉시 중단 기능을 표시한다.
- RULE-007: 외부 접속은 HTTPS/WSS를 사용한다. 개발 HTTP는 loopback으로 제한한다. 비밀번호·토큰·입력 문자열·원본 화면은 로그나 Git에 저장하지 않는다. 운영자 관리 상태와 원격 제어 권한을 혼동하지 않는다.
- RULE-008: 연결·포커스 상실 시 눌린 키와 마우스 버튼을 해제한다. 호스트 OS의 입력 권한 제한을 우회하지 않는다. 에이전트는 외부에서 들어오는 포트를 열지 않는다.

## 협업과 변경 기록

- RULE-009: 설계 변경은 `docs/decisions.md`, API/통신 변경은 `docs/protocol.md`, 재현 방법·검증 결과는 `docs/validation.md`, 사용자 영향은 `CHANGELOG.md`에 함께 기록한다.
- RULE-010: 새 규칙은 이 파일에 고유 ID와 함께 추가한다. 기존 결정을 바꿀 때 이전 기록을 지우지 않고 대체 이유를 남긴다. 제안을 사용자 확정 사항으로 바꾸지 않는다.
- RULE-011: 일반 협업은 작업 브랜치와 PR을 사용한다. 이번 초기 구현은 사용자가 명시한 대로 `main`에 커밋·푸시한다. 강제 푸시하지 않고 원격 변경이 있으면 통합 후 검증한다.
- RULE-012: 기능 변경에는 해당 위험을 검증하는 테스트를 추가한다. 인증·소유권·세션 철회·연결 중계는 통합 테스트로 검증한다. 통과한 검사를 이유 없이 반복하지 않는다.
- RULE-013: UTF-8, LF, 고정된 의존성 잠금 파일을 사용한다. 런타임 DB·빌드 결과·개인 환경은 Git 제외 경로에 둔다. 새 외부 의존성의 버전·라이선스·출처를 기록하며 제품 라이선스는 임의로 결정하지 않는다.
- RULE-014: 사용자 선택(2026-10-15)에 따라 프로젝트 라이선스는 MIT다. 의존성의 기존 저작권·라이선스 고지는 유지한다. 웹 빌드와 agent 패키지에 원문 고지를 포함하며 누락된 런타임 고지가 있으면 패키징을 실패시킨다.
- RULE-015: package.json이 앱 버전 기준이다. `npm run version:set -- X.Y.Z`로 lock/.NET 버전을 동기화한다. 태그와 소스 버전이 다르면 릴리즈를 금지한다. 변경 내용과 검증을 버전별 릴리즈 노트로 남긴다.
- RULE-016: 검증 통과 후 버전별 ZIP/SHA-256/manifest를 draft Release에 모두 업로드하고 마지막에 공개한다. 이미 공개한 버전 파일은 덮어쓰지 않는다. latest는 안정 릴리즈를 뜻하며 조회 실패/캐시/로컬 개발 빌드를 구분한다.
- RULE-017: agent 업데이트 확인은 비밀값 없이 수행한다. 다운로드 링크는 설정한 GitHub 저장소의 HTTPS Release 자산만 사용한다. 실행 중 파일을 자동 교체하거나 다운로드한 프로그램을 조용히 실행하지 않는다.
- RULE-018: 실제 OS 입력 자동 검사는 명시적으로 활성화한 폐기 가능한 Windows VM에서만 수행한다. 물리 작업 PC에서는 실행을 거부한다. 배포 ZIP을 웹에서 내려받아 해시/고지를 확인하고, 실제 agent GUI와 웹을 거쳐 테스트 창의 결과를 검증한다. 준비·빌드 성공을 VM 검증 성공으로 기록하지 않는다.
- RULE-019: 사용자의 Actions 한도 우려(2026-10-15)에 따라 공개 저장소의 표준 러너만 사용하고 Actions 캐시/아티팩트 저장을 사용하지 않는다. 비공개 전환 시 자동 CI를 건너뛰며 비용 정책을 먼저 재검토한다. 유료 러너·예산 증액·결제 설정 변경은 현재 요청 범위에 포함하지 않는다.
- RULE-020: CI action은 공식 릴리즈와 `action.yml`의 지원 실행 엔진을 확인하고 정확한 커밋 SHA로 고정한다. action 업데이트 시 기본값 변경을 검토하고 자동 패키지 캐시를 명시적으로 비활성화하여 RULE-019를 유지한다. 게시한 릴리즈의 태그/바이너리는 CI 설정을 갱신해도 변경하지 않는다.
